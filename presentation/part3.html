PATH PLANNING VS MOTION CONTROL

AN IMPORTANT DISTINCTION

  • There is an important distinction to be made before we start: the distinction between path planning and motion control. This is necessary because the lines between them will become somewhat blurred starting in this lesson.

  • Consider that we have a system composed of one or more robots, with a configuration space \(\mathcal{Q}\). Suppose this configuration is controlled through a control input \(u\) (for example, a manipulator's joint velocity). There is a subset \(\mathcal{Q}_{safe} \subseteq \mathcal{Q}\) that we want to stay within (e.g., to ensure obstacle avoidance, self-collision avoidance, and joint limit enforcement). Furthermore, we also have constraints on the input, \(u \in \mathcal{U}_{safe}\). Finally, we have a starting configuration \(q_0\) and a goal configuration \(q_{F}\).

PATH PLANNING VS MOTION CONTROL

PATH PLANNING

  • In path planning, we only care about connecting \(q_0\) and \(q_{F}\) with a continuous path \(\mathcal{P}\), while staying within \(\mathcal{Q}_{safe}\).

  • It does not consider the constraint \(u \in \mathcal{U}_{safe}\), nor how to compute \(u\) to track this path.

  • Popular algorithms include RRT (and its numerous variants), PRM, CHOMP, etc.

  • This is not within the scope of this class, but there is a course entirely dedicated to it here in PPGEE.

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL

  • In motion control, we are now concerned with the control input \(u\). Usually, we obtain a path \(\mathcal{P}\) from a motion planning algorithm, and the motion control module should track this path while ensuring \(u \in \mathcal{U}_{safe}\).

  • But does motion control disregard \(q \in \mathcal{Q}_{safe}\)?

  • This is not wise! What if, for example, an obstacle (like a moving one) appears that was not considered during motion planning?

  • Thus, it is wise to treat the constraint \(q \in \mathcal{Q}_{safe}\) as an additional safety layer. This is precisely what we call Constrained Robotic Control!

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • We can also differentiate the two from the point of view of locality. Path planning is global: it gathers information from the entire configuration space to make its plan and is therefore more holistic.

  • Motion control, on the other hand, is (usually) local: it relies only on information near the current configuration \(q\) to compute the control input, and is therefore more myopic. For example, motion control often uses the gradient of the distance to obstacles at the current configuration \(q\).

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • The tradeoff is between being fast and being able to handle more complex problems.

  • Path planning takes more time to compute (because it must process more information), whereas motion control is usually much faster and more suitable for reacting to rapid changes.

  • On the other hand, depending on how much the environment has changed compared to when the path \(\mathcal{P}\) was obtained, motion control alone may not be able to solve the problem. Although it may avoid collisions, it could get stuck. In such cases, it becomes necessary to call an (expensive) motion planning algorithm again.

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • The lines between the two are somewhat blurred, though, because some motion control algorithms — such as the ones we will see in this class — may be capable of solving simple instances of the problem of going from one point to another while respecting the constraints, without requiring an explicit path from path planning.

  • Keep in mind, however, that motion planning is often necessary.

GUIDANCE VECTOR FIELDS

  • Lets start with a basic, unconstrained (i.e., \(\mathcal{U}_{safe}\) is everything) motion control algorithm that does not implement an additional safety layer.

  • Suppose we have a point \(q \in \mathbb{R}^n\) and an one-dimensional curve \(\mathcal{P} \subseteq \mathbb{R}^n\) we want to track. We assume that we command the point's velocity \(\dot{q}=u\). Devise a controller to, from wherever you are, go to this curve and keep tracking it.

  • The most popular approach is to do trajectory tracking: parametrize this trajectory into a function \(q_d: \mathbb{R} \mapsto \mathbb{R}^n\) and use a proportional controller plus feedforward: $$ u(t) = \dot{q}_d(t) + K_p(q_d(t)-q(t)).$$

  • This is pretty easy to implement, but it forces the point \(q\) to be at point \(q_d(t)\) at time \(t\) , which not necessarily is a requirement (except in very specific situations, like a drone pursuing an enemy drone).
  • Thus, often it is much better to do path tracking instead: we dont care too much that we have to be at a specific point at a specific time, as long as we stay in the curve following it.

  • In that case, a popular class of algorithms is Guidance Vector Fields (GVF), that establishes a velocity for each point in the space such that if the point follows this velocity, it tracks the curve.

  • UFMG has a good tradition of researching such vector fields. It started with Gonçalves et. al (2010), but the approach I will show here is the updated and improved version proposed in Adriano et. al (2019) (please cite these papers!).

GUIDANCE VECTOR FIELDS

  • To use the algorithm the curve \(\mathcal{P}\) should be differentiable and without self-intersections.

  • Given a point \(q\) and a curve \(\mathcal{P}\), we can compute the vector field \(\Psi_{\mathcal{P}}(q)\) as follows:
  • First we compute the projection \(\Pi_{\mathcal{P}}(q)\) of the point \(q\) into \(\mathcal{P}\).

  • We usually do this by discretizing the curve \(\mathcal{P}\) into points \(c[i]\) very close to each other, and testing each one for the minimum. We find one (because there can be more than one) minimum index \(i_{min}(q)\). We then use $$\Pi_{\mathcal{P}}(q) = c[i_{min}(q)].$$

  • Usually we dont have much points (around 1000), so that is not that bad.

  • We also store the P2S-HSD \(E_{\mathcal{P}}(q)\).
  • We then compute the normal vector \(N_{\mathcal{P}}(q)\), which is the normalized vector from point \(q\) to the projection: $$N_{\mathcal{P}}(p) = \frac{q- \Pi_{\mathcal{P}}(q)}{\|q - \Pi_{\mathcal{P}}(q)\|}.$$

  • This vector is undefined when \(q- \Pi_{\mathcal{P}}(q)=0\), i.e., when \(p \in \mathcal{P}\). But this is not a problem.
  • We then compute the tangent vector \(T_{\mathcal{P}}(q)\). This is the normalized vector tangent to the curve \(\mathcal{P}\) at the point \(\Pi_{\mathcal{P}}(q)\), and can be computed with the previous \(i_{min}(q)\): $$T_{\mathcal{P}}(q) = \frac{ c[i_{min}(q)+1] - c[i_{min}(p)]}{\| c[i_{min}(q)+1] - c[i_{min}(q)] \|}.$$

  • It can be shown (and this is very important for the algorithm) that \(N_{\mathcal{P}}(q)\) and \(T_{\mathcal{P}}(q)\) are orthogonal to each other.

  • Note that the order in which the points \(c[i]\) are (clockwise or counterclocwise) determines the direction of path tracking we want.

  • Two pretty common implementation errors is to have the points not very close enough, and, also, having repeated points. So, make them close enough and remove repeated (or extremely close) points.
  • We have all that we need to compute \(\Psi_{\mathcal{P}}(p)\). The idea is that the normal vector makes the point converge to (any point) in the curve, and the tangent vector makes the point \(q\) move along the curve.

  • The resulting velocity vector is a weighted sum of the two vectors: $$\Psi_{\mathcal{P}}(q) = G(q) N_{\mathcal{P}}(q) + H(q) T_{\mathcal{P}}(q)$$ for two scalars \(G(q),H(q)\) so when we are far away to the curve, \(G\) should be large and \(H\) small, whereas when we are close to the curve, the opposite happens.

  • In special, when the distance to the curve is zero, \(G\) should be zero. Furthermore, \(H\) should never vanish when \(p \in \mathcal{P}\).
  • A popular approach is to choose: $$G(q) = v_{c} \frac{2}{\pi} atan\big(\alpha E_{\mathcal{S}}(q)^{\beta}\big)$$ $$H(q) = \sqrt{v_c^2-G(q)^2}$$ for positive parameters \(v_c,\alpha,\beta\) and "atan" being the arctangent function in radians.

  • The benefit of this choice is that \(\|\Psi_{\mathcal{P}}(q)\|\) is constant, with value \(v_c\). The parameters \(\alpha\) and \(\beta\) controls how aggressive is the convergence. Usually we fix \(\beta=1/4\) and modify only \(\alpha\).

  • The larger is \(\alpha\), the more aggressive is the controller with regards to convergence. It, however, can generates accelerations that the robot cant follow.

CONTROL BARRIER FUNCTIONS

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Control Barrier Functions (CBFs, for short) refer both to a technique used to enforce constraints within a control loop, and to the class of functions that play a central role in this technique.

  • The idea is very simple: given a constraint that depends only on the configuration \(q \in \mathbb{R}^n\), find a differentiable function \(B: \mathbb{R}^n \mapsto \mathbb{R}\) such that the constraint can be expressed as: $$B(q) \geq 0.$$

  • This idea is very similar to the task function approach, which models the task as \(r(q) = 0\). The way we enforce this constraint is also quite similar to how we ensure convergence of the task function to \(0\).

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • In the most basic version of the task function approach, \(r \rightarrow 0\) is achieved by specifying that the control input \(u\) should satisfy \(\frac{d}{dt} r(q) = -Kr(q)\), for a an appropriate scalar \(K>0\). Analogously, we enforce the constraint \(B(q) \geq 0\) by choosing (somehow) the control input \(u\) such that: $$\frac{d}{dt}B(q) \geq -\eta B(q).$$ for a positive scalar constant \(\eta\).

  • It can be shown that this ensures \(B(q(t)) \geq 0\) for all \(t \geq 0\), as long as \(B_0 = B(q(0)) \geq 0\) (i.e., the constraint holds at time \(t = 0\)). This can be proved by multiplying the inequality by the nonnegative term \(e^{\eta t}\). Then: $$ e^{\eta t}\frac{d}{dt}B(q(t)) \geq -e^{\eta t}\eta B(q(t)) \ \rightarrow \ $$ $$ e^{\eta t}\frac{d}{dt}B(q(t)) + e^{\eta t}\eta B(q(t)) \geq 0 \ \rightarrow \ \underbrace{\frac{d}{dt}\Big(e^{\eta t} B(q(t))\Big)}_{ \mbox{product rule} } \geq 0.$$

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Note that we can preserve the inequality when multiplying by the integrating factor \(e^{\eta t}\), because it is always nonnegative.

  • We then integrate both sides from \(0\) to \(t \geq 0\). Since the upper limit of the integral, \(t\), is greater than or equal to the lower limit, \(0\), the inequality is preserved. Thus: $$\int_0^t \frac{d}{d \tau}\Big(e^{\eta \tau} B(q(\tau))\Big)d\tau \geq 0 \rightarrow e^{\eta t} B(q(t)) - B_0 \geq 0.$$

  • By rearranging, we obtain: $$ B(q(t)) \geq e^{-\eta t}B_0 $$ which makes it clear that if \(B_0 \geq 0\), then \(B(q(t)) \geq 0\) for all \(t \geq 0\). Furthermore, as \(t \rightarrow \infty\), we recover the original constraint \(B(q(t)) \geq 0\).

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Thus, we transformed the algebraic constraint \(B(q(t)) \geq 0\) into a differential constraint: \(\frac{d}{dt} B(q(t)) \geq -\eta B(q(t))\).

  • But how do we choose the control input \(u\) to enforce this constraint?

  • To answer this question, we need to understand how the configuration \(q\) and the control input \(u\) are related, and also define our task (e.g., reaching a target pose for a manipulator). After all, \(B(q) \geq 0\) is not exactly our task, but rather a constraint on the task (such as obstacle avoidance).

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Let's start by assuming that $$\dot{q} = u$$ (i.e., first-order kinematic control). For the task, let's ignore motion planning for now and assume that our task is time-invariant. That is, we have a time-invariant task function \(r: \mathbb{R}^n \mapsto \mathbb{R}^m\) that models the task. Furthermore, suppose we have more than one constraint \(B_k(q) \geq 0\); say, exactly \(s\) constraints.

  • If we had no constraints, we would simply enforce \(\dot{r} = -Kr \rightarrow \frac{\partial r}{\partial q}(q)u = -Kr(q)\) (in the most basic version of the task function approach). However, we also need to consider the constraints, which can be enforced by \(\dot{B}_k \geq -\eta_k B_k\) for positive scalar constants \(\eta_k > 0\).

  • By the chain rule, the CBF constraints can be written as: $$\frac{\partial B_k}{\partial q}(q)u \geq -\eta_k B_k(q).$$

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • One initial idea is as follows: at each time step, we measure the configuration \(q\), and set up a system of linear equations and inequalities for the variable \(u\): $$\frac{\partial r}{\partial q}(q)u = G(r(q))$$ $$\frac{\partial B_k}{\partial q}(q)u \geq -\eta_k B_k(q)$$ for \(k = 1, \ldots, s\) and with a function \(G\) with the properties we discussed here.

  • There are efficient algorithms to compute such a \(u\), if it exists. The issue here is that, unless the robot has many degrees of freedom, the equality \(\frac{\partial r}{\partial q}(q)u = G(r(q))\) already consumes almost all of them, and the remaining ones may not be sufficient to satisfy the CBF constraints.

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Let's change the formulation. The constraints \(B_k(q) \geq 0\) are usually hard constraints (such as obstacle avoidance). The task, however, is typically something we would like to accomplish, but failing to do so would not result in a critical failure.

  • Thus, instead of enforcing \(\frac{\partial r}{\partial q}(q)u = G(r(q))\) exactly, we could try to minimize the error: $$ \min_{u} \left\| \frac{\partial r}{\partial q}(q)u - G(r(q)) \right\|^2. $$

  • We can then assemble an optimization problem to find the control input (i.e., the configuration velocity) \(u\).

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Thus, we have the following formulation: $$\min_{u} \left\| \frac{\partial r}{\partial q}(q)u -G(r(q)) \right\|^2$$ $$\mbox{such that}$$ $$\frac{\partial B_k}{\partial q}(q)u \geq -\eta_k B(q) \ , \ k=1,..,s$$

  • Hence, we could set up this optimization problem at each time step, solve for \(u = \dot{q}\), and send it to the robot. Rinse and repeat in a closed loop until (hopefully) convergence.

  • It can be shown that if \(q(0)\) starts without violating none of the constraints \(B_k(q) \geq 0\), that this optimization problem is always feasible, furthermore, that the closed control loop \(\dot{q} = u(q)\) is Lyapunov stable (not necessarily asymptotically Lyapunov stable, however).

  • Ok. But how do we solve this optimization problem?

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • We can expand the squared norm to write the objective function as: $$ u^\top \frac{\partial r}{\partial q}(q)^{\top}\frac{\partial r}{\partial q}(q)u - 2G(r(q))^\top\frac{\partial r}{\partial q}(q)u + \|G(r(q))\|^2.$$
  • Let $$H = 2\frac{\partial r}{\partial q}(q)^{\top}\frac{\partial r}{\partial q}(q) \in \mathbb{R}^{n \times n}$$ and $$f = -2\frac{\partial r}{\partial q}(q)^{\top}G(r(q)) \in \mathbb{R}^n$$ Furthermore, let \(A \in \mathbb{R}^{s \times n}, b \in \mathbb{R}^s\) matrices in which the \(i^{th}\) row of \(A\) is \(\frac{\partial B_k}{\partial q}(q)\) and \(i^{th}\) entry of \(b\) the scalar \(-\eta_k B_k(q)\). Finally, let \(c = \|G(r(q))\|^2\).

CONTROL BARRIER FUNCTIONS

CONVEX QUADRATIC PROGRAM

  • Under these definitions, we can rewrite our optimization problem as: $$\min_{u} \frac{u^\top H u}{2} + f^{\top} u + c $$ $$\text{such that} \ Au \geq b.$$

  • This is called a quadratic program. If \(H\) is a positive definite matrix, it is a convex quadratic program (CVX-QP); and if \(H\) is strictly positive definite, it is a strictly convex quadratic program.

  • Obviously, the second one is a convex optimization problem, and the last one is a strictly convex optimization problem.

  • The constant \(c\) is often disregarded, as it does not affect the optimal solution \(u\).

CONTROL BARRIER FUNCTIONS

CONVEX QUADRATIC PROGRAM

  • Convex or strictly convex quadratic programs can be solved very efficiently, even for very large problems.

  • Non-strictly convex problems, as we know, do not necessarily have a unique solution. This is problematic in control, as it can cause the control input \(u(t)\) to become discontinuous — there may be a "jump" from time \(t\) to time \(t + dt\).

  • In our case, since \(H = \frac{\partial r}{\partial q}^\top \frac{\partial r}{\partial q}\), the matrix \(H\) is always positive semidefinite by construction (any matrix of the form \(H = M^{\top}M\) is). However, it is not necessarily positive definite.

  • Thus, it is beneficial to add \(2 \epsilon I_{n \times n}\) to this matrix, for a small positive \(\epsilon\). This ensures that the resulting \(H\) is positive definite.

  • This is a regularization technique, and it is equivalent to adding \(\epsilon \|u\|^2\) to the objective function — the same trick used in the damped pseudoinverse.

EXAMPLE 1: BASIC EXAMPLE

  • Assume a 2D point with configuration \(q \in \mathbb{R}^2\). We want to converge to a point \(q_F = (1.5 \ \ 0)^\top \) and avoid a circle \( \|q\| \leq 1 \).

  • We can use as a task function \(r(q) = q-q_F\), \(G(r)=-Kr\) and as a CBF function \( B(q) = \|q\| - (1 + \delta) \geq 0 \). The value \(\delta\) is a safety margin.

  • In this case, \(\frac{\partial r(q)}{\partial q} = I_{2 \times 2}\), \(\frac{\partial B(q)}{\partial q} = q^{\top}/\|q\|\).

  • Thus, the optimization problem is: $$\min_{u} \|u+K(q-q_F)\|^2 + \epsilon \|u\|^2$$ $$\mbox{subject to}$$ $$\frac{q^{\top}}{\|q\|} u \geq -\eta \Big(\|q\|-1-\delta\Big).$$

ADDING INPUT CONSTRAINTS

  • We can easily add constraints \(u \in \mathcal{U}_{safe}\) as input limits: $$ \underline{u}_{i} \leq u_i \leq \overline{u}_{i} $$ and the resulting problem is still a CVX-QP since the constraint is linear.

TIME-VARIANT CONSTRAINTS

  • Just like time-varying tasks, CBF constraints can be time-varying as well. For example, a moving obstacle.

  • In this case, the constraint is \(B(q,t) \geq 0\) and, from the chain rule, the specification \(\frac{d}{dt} B(q,t) \geq -\eta B(q,t)\) can be written as: $$\frac{\partial B(q,t)}{\partial q}u \geq -\eta B(q,t)-\frac{\partial B(q,t)}{\partial t} $$ and thus we have the extra term \(\frac{\partial B(q,t)}{\partial t}\). This is similar to the feedforward term \(\frac{\partial r(q,t)}{\partial t}\) in the task function approach, and in practice, it could be difficult to find or estimate as well.

CONTROL BARRIER FUNCTIONS

GENERALIZING A LITTLE BIT

  • Just like in task-space kinematic control, the right-hand side of the CBF constraint can be something more general than \(-\eta B(q)\) for a positive scalar \(\eta\).

  • Intuitively, the constraint \(\dot{B}(q) \geq -\eta B(q)\) limits the speed \(\dot{B}\) at which the frontier \(B(q) = 0\) can be approached (remember that approaching means negative \(\dot{B}\)). You can see that the closer \(B(q)\) is to zero, the less negative \(-\eta B(q)\) becomes, which means that the controller should be more cautious and approach with lower speeds. When \(B(q) = 0\), we enforce \(\dot{B}(q) \geq 0\); that is, we can no longer approach, only move away from the boundary.

  • Thus, it is intuitive that we can generalize this to $$\dot{B} \geq -\kappa(B) $$ where \(\kappa\) is a \(\mathcal{K}_{\infty}\) function (i.e., increasing, continuous, positive, and satisfying \(\kappa(0) = 0\), \(\kappa(\infty) = \infty\)).

CONTROL BARRIER FUNCTIONS

SECOND ORDER KINEMATIC CONTROL

  • What if our system model is $$\ddot{q} = u $$ (i.e., acceleration control) instead of \(\dot{q}=u\)?

  • In that case, the CBF constraint \(\dot{B} \geq -\eta B\) won't work, because from the chain rule it becomes \(\dot{B} = \frac{\partial B}{\partial q} \dot{q} \geq -\eta B\). Note that this formula does not contain the input variable \(u\), and thus we have no direct way to influence the system to guarantee \(B(q) \geq 0\).

  • We can instead use a second-order CBF constraint: $$\ddot{B} \geq -2\eta \dot{B} - \eta^2 B $$ for \(\eta > 0\).

CONTROL BARRIER FUNCTIONS

SECOND ORDER KINEMATIC CONTROL

  • This can be written, using the chain rule, as: $$\frac{\partial B}{\partial q}(q)u \geq -2\eta \frac{\partial B}{\partial q}(q)\dot{q} - \eta^2 B(q) - \dot{q}^\top \frac{\partial^2 B}{\partial q^2}(q)\dot{q}. $$

  • Note that the right-hand side depends only on \(q,\dot{q}\), which must be measured to implement the constraint.

  • It can be shown that, if this inequality is satisfied: $$B(q(t)) \geq \Big( B_0 + \big( \dot{B}_0 + \eta B_0 \big)t \Big)e^{-\eta t}$$ for all \(t \geq 0\), where \(\dot{B}_0 = \frac{\partial B}{\partial q}(q(0))\dot{q}(0)\) is the initial value of \(\frac{d}{dt} B(q(t))\).

  • It is a nice calculus exercise to show that if \(B_0 \geq 0\) and \(\dot{B}_0 + \eta B_0 \geq 0\), then \(B(q(t)) \geq 0\) for all \(t\). This means we should start without violating the constraint, and also with an initial approach speed \(\dot{B}_0\) that is not too fast relative to how far we are from violating the constraint.

CONTROL BARRIER FUNCTIONS

SECOND ORDER KINEMATIC CONTROL

  • We have to change the objective function as well. Let's start with the task-function approach. For the same reasons as before, we cannot simply try to enforce \(\dot{r} = \frac{\partial r}{\partial q}\dot{q} = G(r)\), since we can no longer directly control \(\dot{q}\).

  • The idea is essentially the same as with second-order CBFs. For \( K \geq 0\), we would like to have: $$\ddot{r} = -2K \dot{r} -K^2 r $$ hold as closely as possible. If \(r \in \mathbb{R}^m\), let \(\Gamma \in \mathbb{R}^m\) be the vector such that the \(i^{\text{th}}\) entry is \(\Gamma_i(q,\dot{q}) = \dot{q}^\top \frac{\partial^2 r_i}{\partial q^2}(q)\dot{q}\), where \(r_i(q)\) is the \(i^{\text{th}}\) entry of \(r(q)\).

  • Thus, we can use the following objective function: $$\min_{u} \ \left\|\frac{\partial r}{\partial q}(q)u + 2K \frac{\partial r}{\partial q}(q)\dot{q} + K^2 r(q) + \Gamma(q,\dot{q})\right\|^2 + \epsilon \|u\|^2$$ where again we include the regularization term \(\epsilon \|u\|^2\).

CONTROL BARRIER FUNCTIONS

SECOND ORDER KINEMATIC CONTROL

  • Many packages, as UAIBot, do not implement the computation of Hessians (task functions, distances, etc...), only Jacobians/gradients. But one useful trick is to note that, for any function \(f: \mathbb{R}^n \mapsto \mathbb{R}\): $$\dot{q}^{\top}\frac{\partial^2 f}{\partial q^2}(q)\dot{q} = \left(\frac{d}{dt}\left(\frac{\partial f}{\partial q}(q)\right)\right)\dot{q}.$$

  • Thus, we can use the approximation, we get \(q,\dot{q}\) and compute: $$ \dot{q}^{\top}\frac{\partial^2 f}{\partial q^2}(q)\dot{q} \approx \frac{1}{2\Delta t}\left(\frac{\partial f}{\partial q}(q+\Delta t \dot{q}) - \frac{\partial f}{\partial q}(q-\Delta t \dot{q}) \right) \dot{q} $$ for a small \(\Delta t\).

  • What if we have to use a path? We can adapt the GVF (which was devised for velocities) to accelerations. One way is a follows: given a GVF \(\Psi_{\mathcal{P}}(q)\) and a constant \(K_{v} > 0\), we can set: $$\Omega_{\mathcal{P}}(q,\dot{q}) = -K_v(\dot{q}-\Psi_{\mathcal{P}}(q))+\frac{\partial \Psi_{\mathcal{P}}}{\partial q}(q)\dot{q}.$$

  • Computing \(\frac{\partial \Psi_{\mathcal{P}}}{\partial q}(q)\) can be tricky. Again, numerical approximations come to rescue us: $$\frac{\partial\Psi_{\mathcal{P}}}{\partial q}(q)\dot{q} = \frac{d}{dt}\Psi_{\mathcal{P}}(q) \approx \frac{\Psi_{\mathcal{P}}(q+\Delta t \dot{q})-\Psi_{\mathcal{P}}(q-\Delta t \dot{q}) }{2\Delta t}.$$

CASE STUDIES

EXAMPLE 1: JOINT LIMITS

  • Suppose we have joint limits \(\underline{q}_i\) (lower) and \(\overline{q}_i\) (upper). We can simply use the CBF functions: $$B_{i}^{JL}(q) = q_i - \underline{q}_i;$$ $$B_{i}^{JU}(q) = \overline{q}_i - q_i.$$

  • The Jacobians are trivial to compute:
    $$B_{i}^{JL}(q) = q_i - \underline{q}_i$$ $$\frac{\partial B_{i}^{JL}}{\partial q}(q) = e_i^{\top};$$ $$\frac{\partial B_{i}^{JU}}{\partial q}(q) = -e_i^{\top}$$ where \(e_i\) is the \(i^{th}\) column of the \(n \times n\) identity matrix.



CASE STUDIES

EXAMPLE 1: JOINT VELOCITY LIMITS

  • Suppose we have joint velocity limits \(\underline{u}_i\) (lower) and \(\overline{u}_i\) (upper). We can trivially implement these constraints directly (without the need to use any CBF): $$u_i \geq \underline{u}_i$$ $$u_i \leq \overline{u}_i \ \rightarrow \ -u_i \geq -\overline{u}_i.$$



CASE STUDIES

EXAMPLE 1: OBSTACLE AVOIDANCE

  • For obstacle avoidance, we consider that the robot is composed of \(v = 1, \dots, V\) objects (spheres, boxes, etc...), and that the static environment is composed of \(w = 1, \dots, W\) objects. For each pair, we compute the Euclidean distance between the \(v^{th}\) robot object at configuration \(q\), \(\mathcal{R}(v, q)\), and the \(w^{th}\) environment object \(\mathcal{O}(w)\): $$ D_{vw}(q) = \sqrt{2\Lambda_{\mathcal{R}(v,q), \mathcal{O}(w)}}.$$

  • Remember that \(\Lambda\) is the set-to-set half squared distance (hence the \(\sqrt{2\Lambda}\) to recover the distance).

  • We can then simply set: $$B^{RO}_{vw}(q) = D_{vw}(q) - \delta$$ where \(\delta\) is a safety margin.



CASE STUDIES

EXAMPLE 1: OBSTACLE AVOIDANCE

  • Can we use the half-squared distance directly? Yes, but although HSD is more convenient theoretically and computationally, in my experience, using the distance is better when implementing safety.

  • We can compute the Jacobian of these functions using the distance Jacobian for the S2S-HSD that we learned to compute, since, from the chain rule: $$ \frac{\partial}{\partial q} B^{RO}_{vw}(q) = \frac{1}{\sqrt{2 \Lambda_{\mathcal{R}(v,q), \mathcal{O}(w)}}} \frac{\partial }{\partial q} \Lambda_{\mathcal{R}(v,q), \mathcal{O}(w)}.$$

  • UAIBot's compute_dist already computes the Euclidean distance and the Euclidean distance Jacobian, thus already implementing this equation.

def fun_G(_r, _param_k):
    m = np.shape(_r)[0]
    out = np.matrix(np.zeros((m,1)))
    for i in range(m):
        out[i,0] = -_param_k * np.sign(_r[i,0]) * np.sqrt(np.abs(_r[i,0]))
       
    return out

def compute_control(_q, _htm_tg, is_handling_disk, care_obstacles):
    
    no_joint = np.shape(robot.q)[0]
    
    A = np.matrix(np.zeros((0,no_joint)))
    b = np.matrix(np.zeros((0,1)))
    
    #Create the CBF constraints for all obstacles:
    if care_obstacles:
        
        #Between the robot and the objects
        for obs in all_obstacles:
            ds = robot.compute_dist(q = _q, obj = obs)
            A = np.vstack((A, ds.jac_dist_mat))
            b = np.vstack((b, -param_eta*(ds.dist_vect-param_obs_delta)))
        
        #If the disk is in the end-effector, it should also be handled
        if is_handling_disk:

            #Call the forward kinematic and differential for the end-effector,
            #since this is where the disk is attaches
            jac, htm = robot.jac_geo(q=_q)
            
            s_e = htm[0:3,-1]
            jac_v = jac[0:3,:]
            jac_w = jac[3:6,:]
            
            for obs in all_obstacles:
                point_disk, point_obs, dist, _ = disk.compute_dist(obs)

                jac_dist = (point_disk - point_obs).T * jac_v + np.cross((point_disk - s_e ).T, (point_disk - point_obs).T)  * jac_w
                A = np.vstack((A, jac_dist))
                b = np.vstack((b, -param_eta*(dist-param_obs_delta)))
                    
    #Create the CBF constraint for joint limits
    A = np.vstack((A, np.identity(no_joint)))
    b = np.vstack((b, -param_eta*(_q-robot.joint_limit[:,0]-param_joint_delta) ))  
    A = np.vstack((A, -np.identity(no_joint)))
    b = np.vstack((b, -param_eta*(robot.joint_limit[:,1]-_q-param_joint_delta) ))  
    
    #Implement velocity limits
    A = np.vstack((A, np.identity(no_joint)))
    b = np.vstack((b, -param_max_qdot*np.matrix(np.ones((no_joint,1))) ))  
    A = np.vstack((A, -np.identity(no_joint)))
    b = np.vstack((b, -param_max_qdot*np.matrix(np.ones((no_joint,1))) ))      
    
    
    #Create the objective function
    r, jac_r = robot.task_function(q=_q, htm_tg=_htm_tg)
        
    H = 2*(jac_r.T * jac_r + param_eps* np.identity(no_joint))
    f = -2*jac_r.T*fun_G(r, param_k)
    
    #Compute the control input
    u = ub.Utils.solve_qp(H, f, A, b)

    return u, np.linalg.norm(r)

EXAMPLE 2: A WAITER MOBILE MANIPULATOR

  • We assume that the transformation between the world frame \(\mathcal{F}_{0}\) and the base frame \(\mathcal{F}_{DH0}\) of the manipulator (frame DH0) is: $$T_0^{DH0}(x,y,\theta) = D(x,y,z_b)R_z(\theta)$$ in which \(D\) is a translation and \(R_z\) a rotation in \(z\). \(z_b\) is a constant.

  • We control \(\dot{q}_m = u_m\) (joint velocity control), and, as far as the base is concerned, we have the nonholonomic system $$\dot{x} = v_b \cos(\theta), \ \dot{y} = v_b \sin(\theta) \ , \ \dot{\theta} = u_{\theta}$$ in which \(v_b \in \mathbb{R}\) is the base's linear speed (forward) and \(u_{\theta}\) the (scalar) angular velocity of the base.

  • But since we only learned how to control systems using CBFs that are either \(\dot{q} = u\) or \(\ddot{q} = u\), we can use the following trick: we assume that we control \(\dot{q} = u\) (i.e., the control variables are \(u_m, u_x, u_y, u_{\theta}\) directly). In order to implement the non-holonomy, we will add the equality constraint: $$\sin(\theta)u_x-\cos(\theta)u_y = 0$$ and, we can compute our real control input \(v_m\) through: $$ v_b = \cos(\theta)u_x+\sin(\theta)u_y$$ once we compute \(u_x, u_y\).

EXAMPLE 2: REDEFINING THE JACOBIAN

  • We will need the geometric Jacobian of a frame \(\mathcal{F}_{i}\) attached to the manipulator considering that now, not only we have the manipulator's joints \(q_m\) but also \(x,y,\theta\).

  • Let \(J_{v}^{m,i}(q_m), J_{\omega}^{m,i}(q_m)\) be the linear and angular velocity Jacobians of this frame, only considering the manipulator. Let \(Q_z(\theta) \in \mathbb{R}^{3 \times 3}\) be the 3D rotation matrix in the \(z\) axis, \(s_e(q) \in \mathbb{R}^3\) the position of the end-effector (world frame), \(p = [x \ \ y \ \ z_b]^{\top}\) and \(e_z = [1 \ \ 0 \ \ 0]^{\top}\). Finally, let \(I_{3 \times 2}\) be the 3x3 identity matrix without the last column. It can be shown that (I will leave as an exercise): $$J_{geo}(q) = \left(\begin{array}{ccc} Q_z(\theta)J_{v}^{i,m}(q_m) & I_{3 \times 2} & e_z \times (s_e(q)-p) \\ Q_z(\theta)J_{\omega}^{i,m}(q_m) & 0_{3 \times 2} & e_z \end{array} \right)$$ which is a \(6 \times (7+3)\) matrix. The first \(7\) columns are respective to \(q_m\), the next two columns respective to \(x,y\), and the last column is respective to \(\theta\).
