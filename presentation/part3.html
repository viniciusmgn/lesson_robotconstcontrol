PATH PLANNING VS MOTION CONTROL

GUIDANCE VECTOR FIELDS

  • A pretty common problem in robotics is as follows: we have a point \(p \in \mathbb{R}^n\) and an one-dimensional curve \(\mathcal{C} \subseteq \mathbb{R}^n\). We assume that we command the point's velocity \(\dot{p}=u\). Devise a controller to, from wherever you are, go to this curve and keep tracking it.

  • The most popular approach is to do trajectory tracking: parametrize this trajectory into a function \(p_d: \mathbb{R} \mapsto \mathbb{R}^n\) and use a proportional controller plus feedforward: $$ u(t) = \dot{p}_d(t) + K_p(p_d(t)-p(t)).$$

  • This is pretty easy to implement, but it forces the point \(p\) to be at point \(p_d(t)\) at time \(t\) , which not necessarily is a requirement (except in very specific situations, like a drone pursuing an enemy drone).
  • Thus, often it is much better to do path tracking instead: we dont care too much that we have to be at a specific point at a specific time, as long as we stay in the curve following it.

  • In that case, a popular class of algorithms is Guidance Vector Fields, that establishes a velocity for each point in the space such that if the point follows this velocity, it tracks the curve.

  • UFMG has a good tradition of researching such vector fields. It started with Gonçalves et. al (2010), but the approach I will show here is the updated and improved version in proposed in Adriano et. al (2019) (please cite these papers!).

GUIDANCE VECTOR FIELDS

  • To use the algorithm the curve \(\mathcal{C}\) should be differentiable and without self-intersections.

  • Given a point \(p\) and a curve \(\mathcal{C}\), we can compute the vector field \(\Psi(q)\) as follows:
  • First we compute the projection \(\Pi_{\mathcal{C}}(p)\) of the point \(p\) into \(\mathcal{C}\).

  • We usually do this by discretizing the curve \(\mathcal{C}\) into points \(c[i]\) very close to each other, and testing each one for the minimum. We find one (because there can be more than one) minimum index \(i_{min}(p)\). We then use $$\Pi_{\mathcal{C}}(p) = c[i_{min}(p)].$$

  • Usually we dont have much points (around 1000), so that is not that bad.

  • We also store the P2S-HSD \(E_{\mathcal{C}}(p)\).
  • We then compute the normal vector \(N_{\mathcal{C}}(p)\), which is the normalized vector from point \(p\) to the projection: $$N_{\mathcal{C}}(p) = \frac{p- \Pi_{\mathcal{C}}(p)}{\|p - \Pi_{\mathcal{C}}(p)\|}.$$

  • This vector is undefined when \(p- \Pi_{\mathcal{C}}(p)=0\), i.e., when \(p \in \mathcal{C}\). But this is not a problem.
  • We then compute the tangent vector \(T_{\mathcal{C}}(p)\). This is the normalized vector tangent to the curve \(\mathcal{C}\) at the point \(\Pi_{\mathcal{C}}(p)\), and can be computed with the previous \(i_{min}(p)\): $$T_{\mathcal{C}}(p) = \frac{ c[i_{min}(p)+1] - c[i_{min}(p)]}{\| c[i_{min}(p)+1] - c[i_{min}(p)] \|}.$$

  • It can be shown (and this is very important for the algorithm) that \(N_{\mathcal{C}}(p)\) and \(T_{\mathcal{C}}(p)\) are orthogonal to each other.

  • Note that the order in which the points \(c[i]\) are (clockwise or counterclocwise) determines the direction of path tracking we want.

  • Two pretty common implementation errors is to have the points not very close enough, and, also, having repeated points. So, make them close enough and remove repeated (or extremely close) points.
  • We have all that we need to compute \(\Psi(p)\). The idea is that the normal vector makes the point converge to (any point) in the curve, and the tangent vector makes the point \(p\) move along the curve.

  • The resulting velocity vector is a weighted sum of the two vectors: $$\Psi(p) = G(p) N_{\mathcal{C}}(p) + H(p) T_{\mathcal{C}}(p)$$ for two scalars \(G(p),H(p)\) so when we are far away to the curve, \(G\) should be large and \(H\) small, whereas when we are close to the curve, the opposite happens.

  • In special, when the distance to the curve is zero, \(G\) should be zero. Furthermore, \(H\) should never vanish when \(p \in \mathcal{C}\).
  • A popular approach is to choose: $$G(p) = v_{c} \frac{2}{\pi} atan\big(\alpha E_{\mathcal{S}}(p)^{\beta}\big).$$ $$H(p) = \sqrt{v_c^2-H(p)^2}.$$ for positive parameters \(v_c,\alpha,\beta\) and "atan" being the arctangent function in radians.

  • The benefit of this choice is that \(\|\Psi(p)\|\) is constant, with value \(v_c\). The parameters \(\alpha\) and \(\beta\) controls how aggressive is the convergence. Usually we fix \(\beta=1/4\) and modify only \(\alpha\).

  • The larger is \(\alpha\), the more aggressive is the controller with regards to convergence. It, however, can generates accelerations that the robot cant follow.
