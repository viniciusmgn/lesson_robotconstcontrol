PATH PLANNING VS MOTION CONTROL

PATH PLANNING VS MOTION CONTROL

AN IMPORTANT DISTINCTION

  • There is an important distinction to be made before we start: the distinction between path planning and motion control. This is necessary because the lines between them will become somewhat blurred starting in this lesson.

  • Consider that we have a system composed of one or more robots, with a configuration space \(\mathcal{Q}\). Suppose this configuration is controlled through a control input \(u\) (for example, a manipulator's joint velocity). There is a subset \(\mathcal{Q}_{safe} \subseteq \mathcal{Q}\) that we want to stay within (e.g., to ensure obstacle avoidance, self-collision avoidance, and joint limit enforcement). Furthermore, we also have constraints on the input, \(u \in \mathcal{U}_{safe}\). Finally, we have a starting configuration \(q_0\) and a goal configuration \(q_{F}\).

PATH PLANNING VS MOTION CONTROL

PATH PLANNING

  • In path planning, we only care about connecting \(q_0\) and \(q_{F}\) with a continuous path \(\mathcal{P}\), while staying within \(\mathcal{Q}_{safe}\).

  • It does not consider the constraint \(u \in \mathcal{U}_{safe}\), nor how to compute \(u\) to track this path.

  • Popular algorithms include RRT (and its numerous variants), PRM, CHOMP, etc.

  • This is not within the scope of this class, but there is a course entirely dedicated to it here in PPGEE.

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL

  • In motion control, we are now concerned with the control input \(u\). Usually, we obtain a path \(\mathcal{P}\) from a motion planning algorithm, and the motion control module should track this path while ensuring \(u \in \mathcal{U}_{safe}\).

  • But does motion control disregard \(q \in \mathcal{Q}_{safe}\)?

  • This is not wise! What if, for example, an obstacle (like a moving one) appears that was not considered during motion planning?

  • Thus, it is wise to treat the constraint \(q \in \mathcal{Q}_{safe}\) as an additional safety layer. This is precisely what we call Constrained Robotic Control!

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • We can also differentiate the two from the point of view of locality. Path planning is global: it gathers information from the entire configuration space to make its plan and is therefore more holistic.

  • Motion control, on the other hand, is (usually) local: it relies only on information near the current configuration \(q\) to compute the control input, and is therefore more myopic. For example, motion control often uses the gradient of the distance to obstacles at the current configuration \(q\).

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • The tradeoff is between being fast and being able to handle more complex problems.

  • Path planning takes more time to compute (because it must process more information), whereas motion control is usually much faster and more suitable for reacting to rapid changes.

  • On the other hand, depending on how much the environment has changed compared to when the path \(\mathcal{P}\) was obtained, motion control alone may not be able to solve the problem. Although it may avoid collisions, it could get stuck. In such cases, it becomes necessary to call an (expensive) motion planning algorithm again.

PATH PLANNING VS MOTION CONTROL

MOTION CONTROL AND PATH PLANNING

  • The lines between the two are somewhat blurred, though, because some motion control algorithms — such as the ones we will see in this class — may be capable of solving simple instances of the problem of going from one point to another while respecting the constraints, without requiring an explicit path from path planning.

  • Keep in mind, however, that motion planning is often necessary.

GUIDANCE VECTOR FIELDS

  • Lets start with a basic, unconstrained (i.e., \(\mathcal{U}_{safe}\) is everything) motion control algorithm that does not implement an additional safety layer.

  • Suppose we have a point \(q \in \mathbb{R}^n\) and an one-dimensional curve \(\mathcal{P} \subseteq \mathbb{R}^n\) we want to track. We assume that we command the point's velocity \(\dot{q}=u\). Devise a controller to, from wherever you are, go to this curve and keep tracking it.

  • The most popular approach is to do trajectory tracking: parametrize this trajectory into a function \(q_d: \mathbb{R} \mapsto \mathbb{R}^n\) and use a proportional controller plus feedforward: $$ u(t) = \dot{q}_d(t) + K_p(q_d(t)-q(t)).$$

  • This is pretty easy to implement, but it forces the point \(q\) to be at point \(q_d(t)\) at time \(t\) , which not necessarily is a requirement (except in very specific situations, like a drone pursuing an enemy drone).
  • Thus, often it is much better to do path tracking instead: we dont care too much that we have to be at a specific point at a specific time, as long as we stay in the curve following it.

  • In that case, a popular class of algorithms is Guidance Vector Fields, that establishes a velocity for each point in the space such that if the point follows this velocity, it tracks the curve.

  • UFMG has a good tradition of researching such vector fields. It started with Gonçalves et. al (2010), but the approach I will show here is the updated and improved version proposed in Adriano et. al (2019) (please cite these papers!).

GUIDANCE VECTOR FIELDS

  • To use the algorithm the curve \(\mathcal{P}\) should be differentiable and without self-intersections.

  • Given a point \(q\) and a curve \(\mathcal{P}\), we can compute the vector field \(\Psi(q)\) as follows:
  • First we compute the projection \(\Pi_{\mathcal{P}}(q)\) of the point \(q\) into \(\mathcal{P}\).

  • We usually do this by discretizing the curve \(\mathcal{P}\) into points \(c[i]\) very close to each other, and testing each one for the minimum. We find one (because there can be more than one) minimum index \(i_{min}(q)\). We then use $$\Pi_{\mathcal{P}}(q) = c[i_{min}(q)].$$

  • Usually we dont have much points (around 1000), so that is not that bad.

  • We also store the P2S-HSD \(E_{\mathcal{P}}(q)\).
  • We then compute the normal vector \(N_{\mathcal{P}}(q)\), which is the normalized vector from point \(q\) to the projection: $$N_{\mathcal{P}}(p) = \frac{q- \Pi_{\mathcal{P}}(q)}{\|q - \Pi_{\mathcal{P}}(q)\|}.$$

  • This vector is undefined when \(q- \Pi_{\mathcal{P}}(q)=0\), i.e., when \(p \in \mathcal{P}\). But this is not a problem.
  • We then compute the tangent vector \(T_{\mathcal{P}}(q)\). This is the normalized vector tangent to the curve \(\mathcal{P}\) at the point \(\Pi_{\mathcal{P}}(q)\), and can be computed with the previous \(i_{min}(q)\): $$T_{\mathcal{P}}(q) = \frac{ c[i_{min}(q)+1] - c[i_{min}(p)]}{\| c[i_{min}(q)+1] - c[i_{min}(q)] \|}.$$

  • It can be shown (and this is very important for the algorithm) that \(N_{\mathcal{P}}(q)\) and \(T_{\mathcal{P}}(q)\) are orthogonal to each other.

  • Note that the order in which the points \(c[i]\) are (clockwise or counterclocwise) determines the direction of path tracking we want.

  • Two pretty common implementation errors is to have the points not very close enough, and, also, having repeated points. So, make them close enough and remove repeated (or extremely close) points.
  • We have all that we need to compute \(\Psi(p)\). The idea is that the normal vector makes the point converge to (any point) in the curve, and the tangent vector makes the point \(q\) move along the curve.

  • The resulting velocity vector is a weighted sum of the two vectors: $$\Psi(q) = G(q) N_{\mathcal{P}}(q) + H(q) T_{\mathcal{P}}(q)$$ for two scalars \(G(q),H(q)\) so when we are far away to the curve, \(G\) should be large and \(H\) small, whereas when we are close to the curve, the opposite happens.

  • In special, when the distance to the curve is zero, \(G\) should be zero. Furthermore, \(H\) should never vanish when \(p \in \mathcal{P}\).
  • A popular approach is to choose: $$G(q) = v_{c} \frac{2}{\pi} atan\big(\alpha E_{\mathcal{S}}(q)^{\beta}\big)$$ $$H(q) = \sqrt{v_c^2-G(q)^2}$$ for positive parameters \(v_c,\alpha,\beta\) and "atan" being the arctangent function in radians.

  • The benefit of this choice is that \(\|\Psi(q)\|\) is constant, with value \(v_c\). The parameters \(\alpha\) and \(\beta\) controls how aggressive is the convergence. Usually we fix \(\beta=1/4\) and modify only \(\alpha\).

  • The larger is \(\alpha\), the more aggressive is the controller with regards to convergence. It, however, can generates accelerations that the robot cant follow.

  • The algorithm also works when \(\mathcal{P}\) is not a closed curve. We just need to adapt \(H(q)\) to vanish at the last point.

  • As said before, \(N_{\mathcal{P}}(q)\) is undefined when \(p \in \mathcal{P}\). This is not a problem because \(G(q)\), that multiplies this term, vanishes when \(p \in \mathcal{P}\), making the resulting \(G(q)N_{\mathcal{P}}(q) = 0\).

  • Remember that it works in n-dimensions! So we can use this to track the path in configuration space for a manipulator, for example.

  • There are many extensions: multiple robots, rigid bodies instead of points, obstacles, using accelerations instead of velocities, etc...

CONTROL BARRIER FUNCTIONS

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Control Barrier Functions (CBFs, for short) refer both to a technique used to enforce constraints within a control loop, and to the class of functions that play a central role in this technique.

  • The idea is very simple: given a constraint that depends only on the configuration \(q \in \mathbb{R}^n\), find a differentiable function \(B: \mathbb{R}^n \mapsto \mathbb{R}\) such that the constraint can be expressed as: $$B(q) \geq 0.$$

  • This idea is very similar to the task function approach, which models the task as \(r(q) = 0\). The way we enforce this constraint is also quite similar to how we ensure convergence of the task function to \(0\).

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • In the most basic version of the task function approach, \(r \rightarrow 0\) is achieved by specifying that the control input \(u\) should satisfy \(\frac{d}{dt} r(q) = -Kr(q)\), for a positive scalar \(K\). Analogously, we enforce the constraint \(B(q) \geq 0\) by choosing (somehow) the control input \(u\) such that: $$\frac{d}{dt}B(q) \geq -\eta B(q).$$ for a positive scalar constant \(\eta\).

  • It can be shown that this ensures \(B(q(t)) \geq 0\) for all \(t \geq 0\), as long as \(B(q(0)) \geq 0\) (i.e., the constraint holds at time \(t = 0\)). This can be proved by multiplying the inequality by the nonnegative term \(e^{\eta t}\). Then: $$ e^{\eta t}\frac{d}{dt}B(q(t)) \geq -e^{\eta t}\eta B(q(t)) \ \rightarrow \ $$ $$ e^{\eta t}\frac{d}{dt}B(q(t)) + e^{\eta t}\eta B(q(t)) \geq 0 \ \rightarrow \ \underbrace{\frac{d}{dt}\Big(e^{\eta t} B(q(t))\Big)}_{ \mbox{product rule} } \geq 0.$$

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Note that we can preserve the inequality when multiplying by the integrating factor \(e^{\eta t}\), because it is always nonnegative.

  • We then integrate both sides from \(0\) to \(t \geq 0\). Since the upper limit of the integral, \(t\), is greater than or equal to the lower limit, \(0\), the inequality is preserved. Thus: $$\int_0^t \frac{d}{d \tau}\Big(e^{\eta \tau} B(q(\tau))\Big)d\tau \geq 0 \rightarrow e^{\eta t} B(q(t)) - B(q(0)) \geq 0.$$

  • By rearranging, we obtain: $$ B(q(t)) \geq e^{-\eta t}B(q(0)) $$ which makes it clear that if \(B(q(0)) \geq 0\), then \(B(q(t)) \geq 0\) for all \(t \geq 0\). Furthermore, as \(t \rightarrow \infty\), we recover the original constraint \(B(q(t)) \geq 0\).

CONTROL BARRIER FUNCTIONS

INTRODUCTION

  • Thus, we transformed the algebraic constraint \(B(q(t)) \geq 0\) into a differential constraint: \(\frac{d}{dt} B(q(t)) \geq -\eta B(q(t))\).

  • But how do we choose the control input \(u\) to enforce this constraint?

  • To answer this question, we need to understand how the configuration \(q\) and the control input \(u\) are related, and also define our task (e.g., reaching a target pose for a manipulator). After all, \(B(q) \geq 0\) is not exactly our task, but rather a constraint on the task (such as obstacle avoidance).

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Let's start by assuming that $$\dot{q} = u$$ (i.e., first-order kinematic control). For the task, let's ignore motion planning for now and assume that our task is time-invariant. That is, we have a time-invariant task function \(r: \mathbb{R}^n \mapsto \mathbb{R}^m\) that models the task. Furthermore, suppose we have more than one constraint \(B_i(q) \geq 0\); say, exactly \(s\) constraints.

  • If we had no constraints, we would simply enforce \(\dot{r} = -Kr \rightarrow \frac{\partial r}{\partial q}(q)u = -Kr(q)\) (in the most basic version of the task function approach). However, we also need to consider the constraints, which can be enforced by \(\dot{B}_i \geq -\eta_i B_i\) for positive scalar constants \(\eta_i > 0\).

  • By the chain rule, the CBF constraints can be written as: $$\frac{\partial B_i}{\partial q}(q)u \geq -\eta_i B_i(q).$$

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • One initial idea is as follows: at each time step, we measure the configuration \(q\), and set up a system of linear equations and inequalities for the variable \(u\): $$\frac{\partial r}{\partial q}(q)u = -Kr(q)$$ $$\frac{\partial B_i}{\partial q}(q)u \geq -\eta_i B_i(q)$$ for \(i = 1, \ldots, s\).

  • There are efficient algorithms to compute such a \(u\), if it exists. The issue here is that, unless the robot has many degrees of freedom, the equality \(\frac{\partial r}{\partial q}(q)u = -Kr(q)\) already consumes almost all of them, and the remaining ones may not be sufficient to satisfy the CBF constraints.

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Let's change the formulation. The constraints \(B_i(q) \geq 0\) are usually hard constraints (such as obstacle avoidance). The task, however, is typically something we would like to accomplish, but failing to do so would not result in a critical failure.

  • Thus, instead of enforcing \(\frac{\partial r}{\partial q}(q)u = -Kr(q)\) exactly, we could try to minimize the error: $$ \min_{u} \left\| \frac{\partial r}{\partial q}(q)u + Kr(q) \right\|^2. $$

  • We can then assemble an optimization problem to find the control input (i.e., the configuration velocity) \(u\).

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • Thus, we have the following formulation: $$\min_{u} \left\| \frac{\partial r}{\partial q}(q)u +Kr(q) \right\|^2$$ $$\mbox{such that}$$ $$\frac{\partial B_i}{\partial q}(q)u \geq -\eta_i B(q) \ , \ i=1,..,s$$

  • Hence, we could set up this optimization problem at each time step, solve for \(u = \dot{q}\), and send it to the robot. Rinse and repeat in a closed loop until (hopefully) convergence.

  • It can be shown that if \(q(0)\) starts without violating none of the constraints \(B_i(q) \geq 0\), that this optimization problem is always feasible, furthermore, that the closed control loop \(\dot{q} = u(q)\) is Lyapunov stable (not necessarily asymptotically Lyapunov stable, however).

  • Ok. But how do we solve this optimization problem?

CONTROL BARRIER FUNCTIONS

FIRST ORDER KINEMATIC CONTROL WITH CBFS

  • We can expand the squared norm to write the objective function as: $$ u^\top \frac{\partial r}{\partial q}(q)^{\top}\frac{\partial r}{\partial q}(q)u + 2Kr(q)^\top\frac{\partial r}{\partial q}(q)u + \|Kr(q)\|^2.$$
  • Let $$H = 2\frac{\partial r}{\partial q}(q)^{\top}\frac{\partial r}{\partial q}(q) \in \mathbb{R}^{n \times n}$$ and $$f = 2K\frac{\partial r}{\partial q}(q)^{\top}r(q) \in \mathbb{R}^n$$ Furthermore, let \(A \in \mathbb{R}^{s \times n}, b \in \mathbb{R}^s\) matrices in which the \(i^{th}\) row of \(A\) is \(\frac{\partial B_i}{\partial q}(q)\) and \(i^{th}\) entry of \(b\) the scalar \(-\eta_i B_i(q)\). Finally, let \(c = \|Kr(q)\|^2\).

CONTROL BARRIER FUNCTIONS

CONVEX QUADRATIC PROGRAM

  • Under these definitions, we can rewrite our optimization problem as: $$\min_{u} \frac{u^\top H u}{2} + f^{\top} u + c $$ $$\text{such that} \ Au \geq b $$

  • This is called a quadratic program. If \(H\) is a positive definite matrix, it is a convex quadratic program; and if \(H\) is strictly positive definite, it is a strictly convex quadratic program.

  • Obviously, the second one is a convex optimization problem, and the last one is a strictly convex optimization problem.

  • The constant \(c\) is often disregarded, as it does not affect the optimal solution \(u\).

CONTROL BARRIER FUNCTIONS

CONVEX QUADRATIC PROGRAM

  • Convex or strictly convex quadratic programs can be solved very efficiently, even for very large problems.

  • Non-strictly convex problems, as we know, do not necessarily have a unique solution. This is problematic in control, as it can cause the control input \(u(t)\) to become discontinuous — there may be a "jump" from time \(t\) to time \(t + dt\).

  • In our case, since \(H = \frac{\partial r}{\partial q}^\top \frac{\partial r}{\partial q}\), the matrix \(H\) is always positive semidefinite by construction (any matrix of the form \(H = M^{\top}M\) is). However, it is not necessarily positive definite.

  • Thus, it is beneficial to add \(2 \epsilon I_{n \times n}\) to this matrix, for a small positive \(\epsilon\). This ensures that the resulting \(H\) is positive definite.

  • This is a regularization technique, and it is equivalent to adding \(\epsilon \|u\|^2\) to the objective function — the same trick used in the damped pseudoinverse.

A FIRST EXAMPLE

  • Assume a 2D point with configuration \(q \in \mathbb{R}^2\). We want to converge to a point \(q_F = (1.5 \ \ 0)^\top \) and avoid a circle \( \|q\| \leq 1 \).

  • We can use as a task function \(r(q) = q-q_F\) and as a CBF function \( B(q) = \|q\| - (1 + \delta) \geq 0 \). The value \(\delta\) is a safety margin.

  • In this case, \(\frac{\partial r(q)}{\partial q} = I_{2 \times 2}\), \(\frac{\partial B(q)}{\partial q} = q^{\top}/\|q\|\).

  • Thus, the optimization problem is: $$\min_{u} \|u+K(q-q_F)\|^2 + \epsilon \|u\|^2$$ $$\mbox{subject to}$$ $$\frac{q^{\top}}{\|q\|} u \geq -\eta \Big(\|q\|-1-\delta\Big).$$

import numpy as np
import matplotlib.pyplot as plt
import uaibot as ub
import matplotlib.patches as patches

#Parameters
kp = 0.5
eta = 0.3
dt = 0.01
tmax = 15
delta = 0.05
eps = 0.01
qF = np.matrix([1.5,0]).T
q0 = np.matrix([-1.5,0.2]).T

#Start simulation
q = q0
hist_q = []

for i in range(round(tmax/dt)):


    hist_q.append(np.matrix(q))
    
    #Assembly the CBF controller
    H = 2*(1+eps)*np.matrix([[1.0,0.0],[0.0,1.0]])
    f = 2*kp*(q-qF)

    B_fun = np.linalg.norm(q)-1-delta
    grad_B_fun = q.T/np.linalg.norm(q)

    A = np.matrix(grad_B_fun)
    b = np.matrix([-eta * B_fun])

    #Compute the control input
    u = ub.Utils.solve_qp(H,f,A,b)
    
    #Integrate the equation \dot{q} = u(q)
    q+= u*dt
 
#Plot image
fig, ax = plt.subplots()
ax.set_aspect('equal')
ax.plot([q[0, 0] for q in hist_q], [q[1, 0] for q in hist_q], color='#81d41a')
ax.scatter([qF[0,0]],[qF[1,0]], color='magenta',s=40)
circle = patches.Circle((0.0, 0.0), radius=1.0, color='#5983b0')  # filled by default
